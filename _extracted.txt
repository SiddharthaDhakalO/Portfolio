What this pack is
This is a companion to your master vision document. The original doc deliberately avoided 3D; this pack pivots the navigation layer to lightweight 3D while reusing all of your existing 2D content (plaques, project case studies, the studio, the gift shop) as overlays. Everything is written for full vibe-coding: a master context preamble you prepend once, then an ordered series of single-task prompts you feed to your agent one at a time.
The build in one line: a museum built entirely from React Three Fiber primitives (no Blender, no modeling), a click-to-glide camera (no physics), free CC0 props/textures where wanted, and your existing 2D screens layered on top as content panels.
How to use it
One prompt at a time. After each prompt, run the dev server and look at the result in the browser before moving on.
Prepend the master context preamble (next section) to every task prompt, exactly as your original methodology specifies.
Get the feel before the looks. Phase 0 proves the camera glide with grey boxes. If movement feels good with boxes, the rest is decoration. Do not skip it.
Commit per component: [museum] add <component>. Branch per phase if you like.
Iterate, don't rewrite. Describe the delta only ('raise the ceiling to 6 units', 'make the glide slower'). Ask for a full rewrite only when a component is fundamentally broken.
When something breaks, use the paste-ready debugging prompts in the appendix.
Keep the master doc open. The overlay content, design tokens, motion tokens, responsive rules and SEO are already specified there; this pack wires them into the 3D shell rather than repeating them.
Master context preamble
Prepend this to every task prompt below. It is the 3D replacement for the 'Museum Aesthetic Snippet' in your master doc.
PROJECT: The Museum of Siddhartha Dhakal — an interactive 3D portfolio.
A museum you EXPLORE: click a wing or an exhibit and the camera glides
there. Each exhibit opens a 2D content panel over the 3D scene.
 
STACK: Next.js (App Router) · React Three Fiber (@react-three/fiber) ·
Drei (@react-three/drei) · Tailwind CSS · Framer Motion (2D overlays) ·
EmailJS + react-hook-form + zod (contact form).
 
HARD RULES:
- NO physics engine (no Rapier / Cannon). Camera moves on click-to-glide
  waypoints only.
- NO Blender / no custom modeling. The museum is built from R3F PRIMITIVES
  (boxGeometry, planeGeometry, cylinderGeometry). Optional props are free
  CC0 GLBs from poly.pizza / quaternius.com / kenney.nl via useGLTF.
- Lighting via Drei <Environment preset="lobby"/> + a FEW <spotLight>s +
  <AccumulativeShadows>. Keep real-time lights to a handful.
- The Canvas is client-only ('use client'); on Next App Router import the
  scene with next/dynamic { ssr:false }.
 
DESIGN TOKENS: bg #0E0E0E · charcoal #141414 · gold #C9A961 ·
white #E8E4DC · Cormorant Garamond (headings) · Inter (body).
Gold is an accent only — never a fill or background.
 
METHOD: Build ONE component. I verify it in the browser, then we continue.
Iterate by describing the delta; do not rewrite whole files unless broken.
The phases
Phase 0 — Scaffold + camera feel (greybox)
Goal — a running app with the Canvas on screen and the click-to-glide camera proven using grey boxes.
Prompt 0.1 — Install & first Canvas
Component: components/museum/Scene.tsx + app/museum/page.tsx
 
Task: Set up React Three Fiber. Install three @react-three/fiber
@react-three/drei. Create Scene.tsx ('use client') exporting a
<Canvas shadows camera={{ position:[0,1.6,6], fov:55 }}> containing a
placeholder floor (planeGeometry 40x40, rotated flat, color #141414) and
<Environment preset="lobby"/>. Create app/museum/page.tsx that imports
Scene via next/dynamic with { ssr:false } and renders it at 100dvh.
 
Acceptance: a dark floor renders, the page is full height, and there are
NO 'window is not defined' / SSR errors in the console.
Prompt 0.2 — Greybox rooms + the glide
Component: components/museum/CameraRig.tsx (+ temporary grey boxes)
 
Task: Add Drei <CameraControls> through a ref inside a CameraRig
component. Place 4 grey box rooms (boxGeometry, neutral colour) at rough
atrium / gallery / studio / gift-shop positions. Add a helper
glideTo(x,z) => controls.setLookAt(x,1.6,z+3, x,1.6,z, true). Make each
grey box clickable to glide the camera to it. No styling — this exists
ONLY to tune the feel.
 
Acceptance: clicking a box smoothly glides the camera to face it; the
motion feels calm, not jarring. Expose smoothTime / distance / fov so I
can tune the feel before we build anything pretty.
Phase 1 — Primitive museum shell
Goal — the atrium and wings built from primitives, joined by doorways/corridors.
Prompt 1.1 — Walls & layout from primitives
Component: components/museum/MuseumShell.tsx
 
Task: Replace the grey boxes with a real layout, primitives only. Build
a central atrium plus three wings (gallery, studio, archive) and a
gift-shop room. Rooms = floor planes + wall boxes (thickness ~0.2), with
GAPS left in the walls as doorways between the atrium and each wing.
Drive it from a data array: rooms = [{ id, center:[x,z], size:[w,d],
walls:[...] }] so the whole layout is editable by numbers. Floor #141414,
walls #0E0E0E. Ceiling optional.
 
Acceptance: the camera can glide from the atrium into each wing through
real doorways; no missing walls, no overlapping boxes.
Prompt 1.2 — Waypoints data + test buttons
Component: lib/waypoints.ts (+ temporary HTML test overlay)
 
Task: Create a typed waypoints map — each room has an eye position and a
look target. CameraRig reads from it. Add named waypoints: atrium,
gallery, studio, archive, giftshop. Wire a temporary plain-HTML button
list (fixed corner) that glides to each waypoint, for testing only.
 
Acceptance: the buttons glide the camera room-to-room correctly and it
always arrives centred and facing into the room.
Phase 2 — Lighting & atmosphere
Goal — it reads as a moody, gold-lit contemporary gallery.
Prompt 2.1 — Lighting rig
Component: components/museum/Lighting.tsx
 
Task: Keep <Environment preset="lobby"/> for ambient + reflections. Add
a SMALL number of warm, low-intensity <spotLight castShadow> aimed down
at the exhibit walls for drama. Add <AccumulativeShadows> +
<RandomizedLight> for soft, baked-looking ground shadows computed once on
load (our no-Blender substitute for baking). Enable shadows on the Canvas.
Keep total real-time lights <= ~6.
 
Acceptance: exhibits sit in warm pools of light against dark walls; soft
floor shadows; stays smooth (~60fps).
Prompt 2.2 — Materials, gold trim & one reflective floor
Component: materials pass on MuseumShell
 
Task: Give walls a matte meshStandardMaterial (roughness ~0.9). Add thin
gold trim as slim boxGeometry strips (#C9A961, metalness 0.8) along wall
bases / doorway edges. Give ONLY the atrium floor a Drei
<MeshReflectorMaterial> with low blur + low mixStrength for a subtle
polished sheen — one floor only, for performance.
 
Acceptance: looks high-end; the reflector is used exactly once; no fps
drop versus Phase 2.1.
Phase 3 — Exhibits + content bridge
Goal — projects hang on the walls; clicking one glides in and signals its 2D panel to open.
Prompt 3.1 — The Exhibit component
Component: components/museum/Exhibit.tsx
 
Task: Build an Exhibit = a gold frame (thin boxGeometry, #C9A961,
metalness 0.8) + a plane textured with a project hero image via Drei
useTexture. Props: position, rotation, image, projectSlug, onSelect.
On click call onSelect(projectSlug). Add a subtle hover (slight scale up /
frame brightens) using a useFrame lerp — no heavy libraries.
 
Acceptance: a framed project image hangs on a wall; hover gives feedback;
click fires onSelect with the correct slug.
Prompt 3.2 — Populate from lib/projects.ts
Component: wire lib/projects.ts -> exhibits along the gallery wing
 
Task: Map over the existing projects array and place one <Exhibit> per
project along the gallery-wing walls, evenly spaced. For each, add a
matching waypoint (eye position directly in front of it) to
lib/waypoints.ts. On select: glide to that exhibit's waypoint, and after
the glide completes, trigger opening the 2D overlay for that slug.
 
Acceptance: every project appears as a framed exhibit; selecting one
glides the camera to it and then signals the overlay to open.
Prompt 3.3 — Selection state bridge
Component: lib/useMuseumStore.ts (zustand; React context is fine instead)
 
Task: Add a tiny store holding { currentRoom, selectedSlug, isOverlayOpen }.
An exhibit click sets selectedSlug and opens the overlay AFTER the camera

timeout matching smoothTime). The 2D overlay layer reads this store;
closing the overlay returns control to the scene.
 
Acceptance: clicking an exhibit reliably opens the correct overlay once
the camera has arrived; closing returns cleanly to the museum.

Appendix — paste-ready debugging prompts
When a step misbehaves, paste the matching prompt (with your error text) instead of guessing. These are the five failures you will actually hit with R3F in Next.js.
A. 'window is not defined' / hydration error
My R3F Canvas throws 'window is not defined' on Next App Router. Make the
scene a client component and import it with next/dynamic { ssr:false }.
Show me the corrected page.tsx and Scene.tsx.
B. Black screen / nothing renders
My R3F scene is black. Check, in order: is there a light or <Environment>?
Is the camera inside a wall or behind geometry? Are mesh positions
sensible? Is the floor facing up? Walk through the likely causes and give
fixes.
C. Texture not appearing
My useTexture image doesn't show on the plane. Check: the file is in
/public and the path is correct, the map is assigned on the material, and
the plane faces the camera (rotation). Give the corrected component.
D. Clicks don't register
onClick on my mesh/group doesn't fire. Explain R3F raycasting
requirements, whether anything is blocking the ray, and how Drei <Bvh>
speeds up selection. Show the corrected component.
E. Low frame rate
My museum drops frames. Audit, in priority order: number of real-time
lights, MeshReflectorMaterial usage, shadow-map size, Canvas dpr, and
texture sizes. Give me a prioritised list of fixes.
